# openSME Compliance

This document describes the compliance testing and reporting infrastructure for openSME.

## Quick Start

Generate compliance reports:

```bash
make compliance
```

This runs the full static test suite and produces timestamped reports in `target/compliance/`:
- `compliance-<timestamp>.json` — Machine-readable JSON report
- `compliance-<timestamp>.md` — Human-readable Markdown report

## Reports

### JSON Report

The JSON report contains:
- Timestamp of the run
- Overall compliance status (PASS/FAIL)
- Exit code of the test suite
- Total duration in seconds
- Command that was executed
- Git information (branch, commit, dirty status)
- Environment information (OS, Python version, hostname)
- Test result counts (passed, failed, warnings, skipped)
- Full stdout and stderr from the test run

### Markdown Report

The Markdown report is designed for human consumption and includes:
- Status summary (PASS/FAIL)
- Timing information
- Git context
- Environment details
- Test result counts
- Full command output
- Error output (if any)

## Usage Examples

```bash
# Run compliance with default output location
make compliance

# Run compliance with custom output directory
python3 scripts/compliance.py /path/to/reports

# Self-check the compliance script
python3 scripts/compliance.py --selfcheck
```

## Integration

### CI/CD

The compliance script is designed to run in CI/CD pipelines. Exit codes:
- `0` — All tests passed, compliance achieved
- `1` — Tests failed, compliance not achieved

Example CI step:

```yaml
- name: Compliance Check
  run: make compliance
```

### Scheduling

Run compliance reports on a schedule to track regression:

```bash
# Daily compliance report
0 2 * * * cd /path/to/openSME-compose && make compliance
```

## Test Suite Layers

The compliance script drives `tests/run.py --static` which executes:

| Layer | Description | Scope |
|-------|-------------|-------|
| Layer 0 | Static validation | YAML lint, compose config, env checks, secret scan |
| Layer 1 | Spec compliance | Docker compose files match service specifications |
| Layer 2 | Contract validation | Networks, ports, health checks, security constraints |

All layers must pass for compliance to be achieved.

## Script Details

The compliance script (`scripts/compliance.py`):
- Uses `argparse` for option parsing
- Runs tests via `subprocess.run()`
- Generates reports with full provenance
- Exit code matches test suite exit code

## Git Information

Reports capture:
- Current branch
- Current commit hash
- Dirty working tree status (uncommitted changes)

This helps correlate compliance results with specific code states.

## Environment Information

Reports capture:
- Operating system and version
- Python version
- Hostname

This helps diagnose environment-specific issues.
