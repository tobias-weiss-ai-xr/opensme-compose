T3-booking-agenda — AI meeting-prep brief on booking notifications
===================================================================
Campaign: ai-deeper (agentflow, worktree tf/T3-booking-agenda).
Extends scripts/booking-notify.sh: before a confirmed booking is posted
to the #support Element room, the LiteLLM gateway turns the booking
fields (guest name, event type, notes) into a one-line German guest
context + 3-5 agenda bullets that are appended to the m.room.message
body. The Matrix notification itself never depends on the LLM — ANY
gateway failure (key unset, network unreachable, timeout, malformed or
empty answer) degrades to a static fallback agenda built from the same
fields, so bookings are still announced.

DESIGN NOTES
  * Helper leg, not host: litellm:4000 is reachable from the opensme-net
    docker network only (verified: host curl fails, helper container
    answers), so the gateway call runs in a python:3.12-alpine container
    (image already present on the host; carries python3 without apk).
  * Secrets discipline unchanged: LITELLM_MASTER_KEY travels via bare
    `docker run -e LITELLM_MASTER_KEY` after an explicit export — the
    key never appears in argv, logs, or the sqlite/curl data paths; the
    helper prints only the model's answer.
  * Output contract: model answers "Kontext: …" then "Agenda:" with
    3-5 "- " bullets (German — house style of the other AI surfaces:
    ai-room-bot replies, SOGo drafts); bash normalizes (blank lines
    dropped, section capped at 12 lines) before embedding, so even a
    chatty model cannot blow up the Matrix body.
  * Notification independence: ai_brief is total (fallback on every
    failure path, including scratch-file and jq failures), so posting,
    state tracking and txnId idempotency behave exactly as before.
  * Retry semantics: the brief is regenerated per attempt — a failed
    send retries with a fresh (possibly different) brief next pass;
    the booking id in the state file is what guarantees never-announce-
    twice, unchanged.

KNOWN LIMITATIONS
  * Briefs are German while the fixed notification skeleton stays
    English — deliberate: all AI-generated content in this stack
    (bot replies, SOGo drafts) is German for the German SME demo.
  * LLM output is nondeterministic between retries of the same booking.
  * LLM_GATEWAY_URL must keep the /v1/ prefix — LLM_BASE (probe origin)
    is derived by stripping the shortest /v1/* suffix, with a fallback
    to http://litellm:4000.
  * No per-call cost/latency guard beyond LLM_TIMEOUT; the short prompt
    answered in ~7.5 s live (glm-5.3-flash, stream:false).
  * Test residue: two e2e bookings ("T3 brief e2e", "T3 apply e2e")
    were created via the public booking page for live verification and
    then flipped to status='cancelled' directly in the calrs db (the
    dashboard admin password is interactive-only and not stored in any
    env file). Their VEVENTs remain in the Radicale booking store —
    inert demo data, same category as earlier e2e leftovers.
