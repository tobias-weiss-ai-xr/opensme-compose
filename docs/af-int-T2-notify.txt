DESIGN NOTES
------------
* Idempotency: posted booking ids are appended to
  /var/lib/calrs/booking-notify.state (INSIDE the calrs-data volume,
  written through the same alpine helper — a plain file, so no sqlite
  write locks against live calrs, and no calendar stop/start cycles).
  A pass refuses to run when the state file is unreadable ("state
  unknown" must never post). Crash between PUT and state append can at
  worst re-send: the booking-id txnId makes the server dedupe it.
* Poll source: SELECT ... FROM bookings b LEFT JOIN event_types e WHERE
  b.status='confirmed' — read-only, helper-mounted :ro.
* Secrets: MATRIX_PASSWORD never printed or traced (set +x); login/send
  bodies go through 0600 temp files (removed via EXIT trap); the access
  token is passed to curl as an -H @file so it never appears in argv or
  URLs. Errors surface errcodes only.
* Rate limits: login honors Synapse 429 retry_after_ms (capped 60s) and
  the access token is reused across passes (whoami-validated) so --loop
  logs in once per process instead of once per poll.
* Modes: default single apply pass; --dry-run strictly read-only and
  always exit 0; --check read-only audit, exit !=0 on failed checks;
  --loop [N] polls every N seconds (default 60).
* Env: MATRIX_USER/MATRIX_PASSWORD/MATRIX_ROOM/MATRIX_DOMAIN documented
  in the header; values load from the repo .env (env-quote-hardened
  loader, byte-identical block from calendar-setup.sh/demo-data.sh) with
  explicit environment winning (docker semantics); every default is
  complete, so a missing .env is only a warning.

KNOWN LIMITATIONS
-----------------
* First apply announces ALL confirmed bookings not yet in the state file
  (the 3-bookings backlog here was intentional and documented); seed the
  state file on the volume to suppress a backlog.
* Notifications are plain m.text (no HTML/formatted_body).
* The booking-created → confirmed transition (if calrs ever gains
  'pending') would need the WHERE clause revisited; today every booking
  row observed carries status confirmed|cancelled only.
