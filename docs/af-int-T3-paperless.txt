1. LIVE BUG #1 — the "verified facts" were stale: consume dir NOT watched
------------------------------------------------------------------------
services/paperless.yml binds ./services/paperless-consume:/consume:ro but
NEVER sets PAPERLESS_CONSUMPTION_DIR, so the paperless consumer polls the
image default /usr/src/paperless/consume (an anonymous volume) and the
host bind is silently ignored — dropping a file into the host consume dir
ingested NOTHING (verified before the fix: 42 s wait, zero consumer log
lines). Additionally the :ro bind would break ingestion even with the env
set: the consumer MOVES processed files out of /consume (they vanish from
the host dir on success), which fails on a read-only mount.

Fix (both in repo services/paperless.yml and applied to the deployed
/opt/opensme-compose/compose/services/paperless.yml — backup at
paperless.yml.bak-T3-20261114, container recreated via compose with the
stack's full config-file list, --no-deps paperless-ngx):
      PAPERLESS_CONSUMPTION_DIR: /consume
      - ./services/paperless-consume:/consume        # was :ro

2. LIVE BUG #2 — fleet firewall broke ALL Stalwart OIDC token validation
------------------------------------------------------------------------
Stalwart (directory=oidc) validates every XOAUTH2 token / REST bearer
against Zitadel userinfo at http://$ZITADEL_DOMAIN:8081/... resolved via
the fleet extra_hosts pin (stalwart-idpplain.yml) to host-gateway
<HOST_GW_IP>:8081 (host traefik, Host-rewrite middleware). Host-side that
route answers fine, but ufw INPUT policy DROP blocked container → host
traffic on :8081, so stalwart's userinfo calls hung:
  - IMAP AUTHENTICATE XOAUTH2 (any user) → client-side timeout
  - POST /api/account/auth (self-service app passwords) → timeout/401
  - stale SOGo-redis session tokens → Zitadel says "access token invalid"
This made app-password minting (scripts/stalwart-app-password.sh) and
webmail IMAP XOAUTH2 dead fleet-wide. Root-cause fix, mirroring the
existing tinyproxy precedent (8888/tcp ALLOW 192.0.2.0/24):
  sudo ufw allow from 192.0.2.0/24 to any port 8081 proto tcp \
       comment 'opensme idpplain backchannel (stalwart userinfo)'
After the rule: TCP OK from the stalwart container, XOAUTH2 IMAP login
works, app-password endpoint answers. NOTE FOR ANSIBLE FLEET: persist this
rule in the web_hosts firewall role.

3. DELIVERABLE — scripts/paperless-intake.sh
--------------------------------------------
Modes:
  --print-sieve   prints the sieve fileinto rule + admin install doc (§4)
  --once          one poll pass (default)
  --loop N        poll every N seconds (INT/TERM-clean)
  --dry-run       list what would drop; writes nothing (incl. state)
  --mailbox NAME  IMAP folder to scan (default INvoices)
  --status        state-file summary
Behavior:
  - IMAP host/port via PAPERLESS_INTAKE_IMAP_HOST/PORT (default
    127.0.0.1:143 host-side; stalwart:143 reachable inside netns)
  - Auth against the OIDC-backed directory (regular passwords are inert,
    docs/SSO.md): PLAIN via app password
    (PAPERLESS_INTAKE_IMAP_USER/_IMAP_PASSWORD; mint ONCE per account with
    scripts/stalwart-app-password.sh <email> paperless-intake) or XOAUTH2
    via PAPERLESS_INTAKE_TOKEN_FILE (live access token, for smoke tests).
  - READ-ONLY IMAP select: never deletes, never flags, never marks seen —
    copy semantics by construction.
  - Every named attachment of every not-yet-handled message is dropped to
    $PAPERLESS_INTAKE_CONSUME_DIR (default /opt/opensme-compose/compose/
    services/paperless-consume) atomically (`.part` + os.replace) as
    <timestamp>-uid<uid>-<sanitized-filename>; paperless never sees partial
    files. sha256 + per-folder UID(+UIDVALIDITY) bookkeeping in
    data/paperless-intake.state.json → no re-drops (verified: immediate
    re-run reports "1 already handled, 0 dropped").
  - Preflight: consume dir exists/writable (root-owned /opt paths → run
    via sudo), exactly one auth source set, python3 present.
  - shellcheck -S warning clean; bash -n clean.
Known limitation (pre-existing, NOT changed — outside this task's focus):
scripts/stalwart-app-password.sh runs its REST call INSIDE the sogo6
container where the corporate proxy env hangs the call; minting works
reliably from the HOST against http://<stalwart-ip>:8080/api/account/auth
(bearer = live OIDC token of the account).
