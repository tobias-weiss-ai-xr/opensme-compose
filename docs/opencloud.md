# OpenCloud — Environment Variables, Integration Patterns & Troubleshooting

> Companion to `.env.example` (sections *OpenCloud Core*, *OpenCloud WebDAV
> Access*, *OpenCloud S3 Access*) and `opencloud/opencloud.yml`.
> See also `docs/opencloud-integration-matrix.md` for the full connectivity
> matrix across openSME services.

OpenCloud (ocis) is openSME's file-sync/share platform. It is fronted by
Traefik at `https://${OPENCLOUD_DOMAIN}` and federates with Zitadel for
browser SSO (OIDC PKCE). Internally the service listens on
`opensme-opencloud:9200`. Storage defaults to the local POSIX `ocis` driver
(volume `opencloud-data`); S3-compatible object storage (SeaweedFS) is used
by the Notes and Invoice Ninja services for media/invoice blobs and is
configured via the shared `OC_S3_*` variables.

This document covers **every operator-facing `CLOUD_*`, `OC_*`, `OPENCLOUD_*`
and S3 variable** — what it does, its default, whether it is required, an
example, and which service(s) consume it — plus common integration patterns
and a troubleshooting runbook.

---

## 1. Environment Variables

Variables are grouped to mirror `.env.example`:

1. **OpenCloud Core** — service identity, SSO, machine auth, SMTP
2. **OpenCloud WebDAV Access** — `CLOUD_*` (portal/LimeSurvey cloud uploads)
3. **OpenCloud S3 Access** — `OC_S3_*` (shared S3 credentials for Notes/Invoice Ninja)
4. **Derived / overlay-only** — set inside `opencloud/opencloud.yml` from the
   variables above; listed for reference (do **not** set these in `.env`).

> **Conventions used below**
> - *Required* = the compose overlay fails fast (`${VAR:?...}`) when unset.
> - *Default* = the value the overlay uses when the variable is unset
>   (`${VAR:-default}`). An empty `Default` cell means "no default / empty".
> - *Used-by* lists the compose service(s) and source file(s).

### 1.1 OpenCloud Core

| Variable | Description | Default | Required | Example | Used-by |
|---|---|---|---|---|---|
| `OPENCLOUD_DOMAIN` | Public hostname served by Traefik. Drives `OC_DOMAIN`, `OC_URL`, the Traefik router rule and the Collabora `aliasgroup1`. | `cloud.opensme.graphwiz.ai` | yes (compose default) | `cloud.home.opensme.graphwiz.ai` | `opencloud` (`opencloud/opencloud.yml`), `collabora`, portal (`OPENCLOUD_URL`), Traefik router (`docker-compose.yml`) |
| `OC_ADMIN_USERNAME` | Bootstrap admin username created on first start. | `admin` | no | `admin` | `opencloud` (`opencloud.yml`) |
| `OC_ADMIN_PASSWORD` | Bootstrap admin password. Rotated in prod. | — (CHANGEME) | **yes** (`${OC_ADMIN_PASSWORD:?}`) | `s3cr3t-pass` | `opencloud` (`opencloud.yml`) |
| `OC_OIDC_CLIENT_ID` | Zitadel OIDC client id for browser SSO. A non-empty value is the opt-in switch — empty falls back to the unregistered `opencloud` label (login dead-ends). Minted by `scripts/zitadel-client.sh --app opencloud`. | `opencloud` (compose default) | no (but SSO needs the minted id) | `opencloud-oidc` | `opencloud` (`opencloud.yml`) |
| `OC_OIDC_CLIENT_SECRET` | OIDC client secret. The persistent client is a **PUBLIC PKCE** app, so `scripts/zitadel-client.sh` deliberately persists an **empty** value — empty is valid here (do **not** use `${...:?}`). | — (empty) | no | (leave empty for PKCE) | `opencloud` (`opencloud.yml`) |
| `OC_INSECURE` | Accept self-signed/internal TLS on inter-service calls. `true` is correct for compose (inter-service traffic stays on the internal network; TLS boundary is Traefik). | `true` | no | `true` | `opencloud` (`opencloud.yml`) |
| `OPENCLOUD_ENABLE_BASIC_AUTH` | Opt-in machine auth (Basic-auth) for service/DAV accounts used by the portal cloud bridge and LimeSurvey cloud sync. Enable together with `CLOUD_WEBDAV_*`. | `NOTIFICATIONS_SMTP_SENDER` | Sender address for OpenCloud notification emails (password-reset / share notifications). The full SMTP relay is configured by the `OC_SMTP_*` vars (see §1.4). | `noreply@${OPENSME_DOMAIN}` | no | `noreply@opensme.example.org` | `opencloud` (`NOTIFICATIONS_SMTP_SENDER`, `opencloud.yml`) |

> **Auto-generated secrets** — `OC_JWT_SECRET`, `OC_TRANSFER_SECRET`,
> `OC_URL_SIGNING_SECRET` are generated by `opencloud init` on first run and
> stored in the `opencloud-config` volume. **Do not** set them in `.env`.

### 1.2 OpenCloud WebDAV Access (`CLOUD_*`)

Used by the **portal cloud bridge** (`portal/src/cloud.rs`) and the
**LimeSurvey cloud-sync sidecar** (`services/limesurvey.yml`) to upload files
and create public read-only share links over WebDAV/OCS. All four empty =
cloud uploads disabled (portal falls back to local `attachments/`; the
LimeSurvey sync sidecar idles). Requires
`OPENCLOUD_ENABLE_BASIC_AUTH=true` (Basic-auth service account).

| Variable | Description | Default | Required | Example | Used-by |
|---|---|---|---|---|---|
| `CLOUD_WEBDAV_URL` | Base WebDAV URL for the service account (internal service address). Point at the OpenCloud DAV endpoint. | — (empty) | no (empty disables cloud uploads) | `http://opensme-opencloud:9200/remote.php/dav/files/uploader` | portal (`docker-compose.yml`), `limesurvey-cloud-sync` (`services/limesurvey.yml`) |
| `CLOUD_WEBDAV_USER` | Basic-auth username for the WebDAV service account (created in OpenCloud's IDM). Often the same as `OC_ADMIN_USERNAME` for a single-account setup. | — (empty) | no | `uploader` | portal, `limesurvey-cloud-sync` |
| `CLOUD_WEBDAV_PASS` | Basic-auth password for the WebDAV service account. Keep secret; rotate via the OpenCloud IDM. | — (empty) | no | `s3cr3t-dav` | portal, `limesurvey-cloud-sync` |
| `CLOUD_SHARE_URL` | Optional override for the OCS shares API endpoint (public share-link creation). Default is derived from `CLOUD_WEBDAV_URL`'s host. Set only when the shares endpoint differs from the WebDAV host. | derived from `CLOUD_WEBDAV_URL` | no | `http://opensme-opencloud:9200/ocs/v2.php/apps/files_sharing/api/v1/shares` | portal (`portal/src/cloud.rs`) |

> **WebDAV/OCS endpoints**
> - DAV: `http://opensme-opencloud:9200/remote.php/dav/files/<user>`
> - OCS shares: `http://opensme-opencloud:9200/ocs/v2.php/apps/files_sharing/api/v1/shares`

### 1.3 OpenCloud S3 Access (`OC_S3_*`)

Shared S3 credentials for the SeaweedFS object store (network-aliased as
`minio` on `opensme-net`, S3 API on `:9000`). `OC_S3_*` is the **single
source of truth**; service overlays map them to their own `AWS_*` /
`AWS_S3_*` env vars. The access/secret pair **must match**
`opencloud/seaweedfs-s3.json`.

| Variable | Description | Default | Required | Example | Used-by |
|---|---|---|---|---|---|
| `OC_S3_ENDPOINT` | S3 endpoint (internal). SeaweedFS serves the S3 API on `:9000` and is aliased as `minio` for backward compatibility with MinIO-era configs. | `http://minio:9000` | no | `http://minio:9000` | `notes` (`AWS_S3_ENDPOINT_URL` hardcoded to `http://minio:9000`), `invoice-ninja` (`AWS_ENDPOINT`/`AWS_URL`) |
| `OC_S3_REGION` | S3 region. Cosmetic for SeaweedFS; some SDKs require a non-empty value. | `us-east-1` | no | `us-east-1` | `invoice-ninja` (`AWS_DEFAULT_REGION`) |
| `OC_S3_BUCKET` | Default S3 bucket name. Per-service buckets are derived by the overlays (e.g. `notes-media`, `invoiceninja`); this is the shared default. | `opencloud` | no | `opencloud` | (documented default; overlays use their own `*_S3_BUCKET`/`AWS_BUCKET`) |
| `OC_S3_ACCESS_KEY` | S3 access key. Must match the `accessKey` in `opencloud/seaweedfs-s3.json`. | `minio` | no (compose default `minio`) | `minio` | `notes` (`AWS_S3_ACCESS_KEY_ID`), `invoice-ninja` (`AWS_ACCESS_KEY_ID`) |
| `OC_S3_SECRET_KEY` | S3 secret key. Must match the `secretKey` in `opencloud/seaweedfs-s3.json`. | — (CHANGEME) | **yes** (`${OC_S3_SECRET_KEY:?}`) | `CHANGEME_minio` | `notes` (`AWS_S3_SECRET_ACCESS_KEY`), `invoice-ninja` (`AWS_SECRET_ACCESS_KEY`) |

> **Per-service bucket overrides** (not `OC_S3_*`, set per service):
> - Notes: `AWS_STORAGE_BUCKET_NAME=notes-media` (hardcoded in `services/notes.yml`)
> - Invoice Ninja: `AWS_BUCKET=${INVOICENINJA_S3_BUCKET:-invoiceninja}`

## 2. Integration Patterns

### 2.1 Portal → OpenCloud WebDAV (poll attachment upload + public share)

The portal cloud bridge (`portal/src/cloud.rs`) reads `CLOUD_WEBDAV_*` +
`CLOUD_SHARE_URL`. When all three `CLOUD_WEBDAV_*` are set, poll attachment
uploads go to OpenCloud over WebDAV and a public read-only share link is
created via the OCS API; otherwise uploads fall back to the local
`attachments/` dir.

```bash
# .env — enable cloud uploads + public share links
OPENCLOUD_ENABLE_BASIC_AUTH=true
CLOUD_WEBDAV_URL=http://opensme-opencloud:9200/remote.php/dav/files/uploader
CLOUD_WEBDAV_USER=uploader
CLOUD_WEBDAV_PASS=CHANGEME_dav
# Optional: override the OCS shares endpoint (default derived from CLOUD_WEBDAV_URL)
# CLOUD_SHARE_URL=http://opensme-opencloud:9200/ocs/v2.php/apps/files_sharing/api/v1/shares
```

Flow:
1. Portal `PUT`s the file to `${CLOUD_WEBDAV_URL}/<poll>/<file>`.
2. Portal `POST`s to the OCS shares endpoint (or `CLOUD_SHARE_URL`) to mint a
   public read-only link.
3. The link is returned to the member and survives poll rotation.

> `OPENCLOUD_ENABLE_BASIC_AUTH=true` is **required** — without it the
> Basic-auth DAV account 500s ("missing claim 'name'"; see §3.2).

### 2.2 LimeSurvey → OpenCloud WebDAV (rclone mirror sidecar)

The `limesurvey-cloud-sync` sidecar mirrors survey uploads to OpenCloud
(`Umfragen/LimeSurvey`) every 60 s using the same `CLOUD_WEBDAV_*` account.
If `CLOUD_WEBDAV_URL` or `CLOUD_WEBDAV_PASS` is empty, the sidecar idles and
the survey tool works standalone.

```bash
# Reuses the same CLOUD_WEBDAV_* as the portal (single service account)
CLOUD_WEBDAV_URL=http://opensme-opencloud:9200/remote.php/dav/files/uploader
CLOUD_WEBDAV_USER=uploader
CLOUD_WEBDAV_PASS=CHANGEME_dav
```

### 2.3 Notes (Impress) → SeaweedFS (S3)

Notes stores media files in SeaweedFS via the S3 API. The endpoint is
hardcoded to `http://minio:9000` (the `minio` network alias); credentials
come from the shared `OC_S3_*`.

```bash
# .env — shared S3 credentials (must match opencloud/seaweedfs-s3.json)
OC_S3_ENDPOINT=http://minio:9000
OC_S3_ACCESS_KEY=minio
OC_S3_SECRET_KEY=CHANGEME_minio
```

Overlay mapping (`services/notes.yml`):
```yaml
AWS_S3_ENDPOINT_URL: "http://minio:9000"          # hardcoded alias
AWS_S3_ACCESS_KEY_ID: ${OC_S3_ACCESS_KEY:-minio}
AWS_S3_SECRET_ACCESS_KEY: ${OC_S3_SECRET_KEY:?OC_S3_SECRET_KEY must be set in .env}
AWS_STORAGE_BUCKET_NAME: notes-media
```

### 2.4 Invoice Ninja → SeaweedFS (S3)

Invoice Ninja stores invoices/PDFs/logos in SeaweedFS with
`FILESYSTEM_DISK=s3`. It reuses the same `OC_S3_*` credentials and adds a
per-service bucket override.

```bash
# .env — shared S3 credentials + per-service bucket
OC_S3_ENDPOINT=http://minio:9000
OC_S3_REGION=us-east-1
OC_S3_ACCESS_KEY=minio
OC_S3_SECRET_KEY=CHANGEME_minio
INVOICENINJA_S3_BUCKET=invoiceninja   # optional override (default: invoiceninja)
```

Overlay mapping (`services/invoice-ninja.yml`):
```yaml
FILESYSTEM_DISK: s3
AWS_ACCESS_KEY_ID: ${OC_S3_ACCESS_KEY:-minio}
AWS_SECRET_ACCESS_KEY: ${OC_S3_SECRET_KEY:?OC_S3_SECRET_KEY must be set in .env}
AWS_DEFAULT_REGION: ${OC_S3_REGION:-us-east-1}
AWS_BUCKET: ${INVOICENINJA_S3_BUCKET:-invoiceninja}
AWS_ENDPOINT: ${OC_S3_ENDPOINT:-http://minio:9000}
AWS_URL: ${OC_S3_ENDPOINT:-http://minio:9000}
AWS_USE_PATH_STYLE_ENDPOINT: "true"   # SeaweedFS speaks path-style HTTP, not HTTPS
```

### 2.5 Collabora (WOPI) ↔ OpenCloud

Collabora edits OpenCloud files over WOPI. It is configured (in
`opencloud/opencloud.yml`) from `OPENCLOUD_DOMAIN` alone — no separate S3 or
WebDAV vars:

```yaml
aliasgroup1: https://${OPENCLOUD_DOMAIN:-cloud.opensme.graphwiz.ai}:443
```

### 2.6 SSO: OpenCloud ↔ Zitadel (OIDC PKCE)

Browser SSO uses a **public PKCE** OIDC client (no secret). On first demo
boot, `scripts/zitadel-client.sh --app opencloud` registers the client and
writes the real `OC_OIDC_CLIENT_ID` / `OC_OIDC_CLIENT_SECRET` back into
`.env`. A non-empty `OC_OIDC_CLIENT_ID` is the opt-in switch.

```bash
# After scripts/zitadel-client.sh --app opencloud has run:
OC_OIDC_CLIENT_ID=opencloud-oidc   # minted id (opt-in switch)
OC_OIDC_CLIENT_SECRET=             # empty — PKCE public client
```

The IdP backchannel needs `host-gateway` (already configured in
`opencloud.yml`) because the public IdP hostname resolves to the Zitadel
container IP internally (plain HTTP :8080 only; TLS lives at the Traefik
edge).

## 3. Troubleshooting

### 3.1 OIDC login dead-ends at `Errors.App.NotFound`

**Cause:** `OC_OIDC_CLIENT_ID` is empty, so compose falls back to the
unregistered `opencloud` label.

**Fix:** Run `scripts/zitadel-client.sh --app opencloud` to register the
client, then ensure the minted id is written to `OC_OIDC_CLIENT_ID` in
`.env` and restart OpenCloud.

### 3.2 Basic-auth / DAV requests return HTTP 500 ("missing claim 'name'")

**Cause:** Basic-auth/DAV accounts cannot carry OpenCloud's default `name`
(displayName) claim, so the account-resolver 500s. This silently breaks the
portal cloud bridge and the LimeSurvey cloud sync.

**Fix:** `opencloud.yml` sets
`PROXY_AUTOPROVISION_CLAIM_DISPLAYNAME=preferred_username` to drive
displayName from `preferred_username`. If you overrode this, restore it.
**Side effect (cosmetic):** OpenCloud's own UI shows login names as display
names; Zitadel/SOGo/portal keep their own names.

### 3.3 WebDAV uploads silently disabled (portal falls back to local files)

**Cause:** One of `CLOUD_WEBDAV_URL` / `CLOUD_WEBDAV_USER` /
`CLOUD_WEBDAV_PASS` is empty, or `OPENCLOUD_ENABLE_BASIC_AUTH` is `false`.

**Fix:**
1. Set all three `CLOUD_WEBDAV_*` values.
2. Set `OPENCLOUD_ENABLE_BASIC_AUTH=true`.
3. Confirm the service account exists in OpenCloud's IDM and the password
   matches.
4. Restart the portal so it picks up the new env.

### 3.4 S3 errors from Notes / Invoice Ninja (`OC_S3_SECRET_KEY must be set`)

**Cause:** `OC_S3_SECRET_KEY` is the only `OC_S3_*` var with a hard
`${...:?}` gate — the overlays fail fast when it is unset.

**Fix:** Set `OC_S3_SECRET_KEY` in `.env` to the value matching
`opencloud/seaweedfs-s3.json` (`secretKey`). Keep the two in sync on
rotation.

### 3.5 S3 403 / signature mismatch after rotating SeaweedFS credentials

**Cause:** `OC_S3_ACCESS_KEY` / `OC_S3_SECRET_KEY` in `.env` drifted from
`opencloud/seaweedfs-s3.json`.

**Fix:** Update **both** the `.env` pair and the `seaweedfs-s3.json`
`accessKey`/`secretKey`, then restart `seaweedfs` and the consuming services
(`notes`, `invoice-ninja`).

### 3.6 Notifications / password-reset emails not delivered

**Cause:** `NOTIFICATIONS_SMTP_*` relay not configured (Stalwart account
missing or credentials wrong). The notifications service binds these
**without** the `OC_` prefix (struct tag `env:"NOTIFICATIONS_SMTP_*"`).

**Fix:** Set `OC_SMTP_HOST`/`OC_SMTP_PORT`/`OC_SMTP_USERNAME`/
`OC_SMTP_PASSWORD` in `.env` and ensure a matching Stalwart account exists.
`NOTIFICATIONS_SMTP_SENDER` only validates the sender format at startup.

### 3.7 Public share links require a password (poll workflow breaks)

**Cause:** OpenCloud defaults to
`OC_SHARING_PUBLIC_SHARE_MUST_HAVE_PASSWORD=true`; automated poll-share
creation can't supply a password.

**Fix:** Set `OPENCLOUD_PUBLIC_SHARE_PASSWORD=false` in `.env` for
deployments that need passwordless read-only public links (the poll
workflow). Leave `true` for general deployments.

### 3.8 `minio` hostname does not resolve

**Cause:** The `seaweedfs` service (in `opencloud/minio.yml`) must be
included via `COMPOSE_FILE=...:opencloud/minio.yml`; it provides the `minio`
network alias that `OC_S3_ENDPOINT=http://minio:9000` depends on.

**Fix:** Include the minio overlay, e.g.
`COMPOSE_FILE=docker-compose.yml:opencloud/opencloud.yml:opencloud/minio.yml`.

### 3.9 IdP backchannel fails (`connection refused` on :443)

**Cause:** Inside the compose network the public IdP hostname resolves to the
Zitadel container IP, where :443 is not listening (TLS lives at Traefik).

**Fix:** Already handled — `opencloud.yml` pins
`${ZITADEL_DOMAIN}:host-gateway` so ocis reaches the edge Traefik on :443.
If you removed `extra_hosts`, restore it.

### 3.10 Debugging env resolution

To confirm the effective values OpenCloud sees at runtime:

```bash
# Print the rendered environment for the opencloud service
docker compose --env-file .env config | sed -n '/services:/,/^volumes:/p' | grep -E 'OC_|CLOUD_|OPENCLOUD_|NOTIFICATIONS_'

# Inspect the running container's env directly
docker exec opensme-opencloud env | grep -E 'OC_|CLOUD_|OPENCLOUD_|NOTIFICATIONS_'
```
