3. DEVIATIONS / FINDINGS
------------------------
D1 (fixed, operational only) — orphaned netns passenger on first run:
   docker-compose.yml merges calendar-radicale into the calendar service's
   network namespace (network_mode: "service:calendar"; traefik labels and
   the DNS aliases 'calendar' + 'calendar-radicale' live on the calendar
   container, pinned IP 172.19.0.250). Run #1's `compose up -d --wait
   calendar` recreated the calendar container (netns owner) but compose did
   NOT recreate radicale (its config hash was unchanged) → radicale kept
   running in the dead netns of the REMOVED previous calendar container
   (loopback only, no eth0). Symptoms: calrs sync "Connection refused"
   against calendar-radicale:5232 (alias → 172.19.0.250, where nothing
   listened), edge /dav → 502, MKCALENDAR → 502. FIX: `docker compose up -d
   --wait calendar calendar-radicale` re-attached the passenger to the new
   netns (V6). RECOMMENDATION (needs a script change → out of T2's
   docs/-only scope): calendar-setup.sh step 3 should bring up BOTH
   services (`dc up -d --wait calendar calendar-radicale`) so any future
   calendar-container recreation re-attaches the passenger automatically.
D2 (cosmetic, script quirk) — step 6 probe never matches:
   The probe greps PROPFIND output for '<c:calendar/>' but Radicale
   serializes '<C:calendar />' (uppercase namespace prefix + space), so the
   "already present" branch never fires; every run falls through to
   MKCALENDAR, which returns 409 on the existing collection and prints the
   benign warn. Harmless (the script proceeds and sync confirms — V4/V5),
   but the warn is misleading on every run. Same docs-only caveat as D1.
D3 Booking root "/" returns 303 → /auth/login (200 followed). The public
   booking page /u/demo/vc returns 200 (V2). Gate's plain `curl -sk`
   exits 0 on the 303 (no --fail), behavior unchanged from before T2.
D4 Backup calendar-setup.sh.bak-20261114 already existed — creation
   skipped per procedure ("if not present").
D5 Deployed script replaced by the 556-line worktree version (adds the T1
   env-quote hardening block); the live .env was clean — no scrub warnings
